# Sigil Factory — 工場ノード / ライン仕様書

更新日: 2026-08-19

この文書は、工場盤面・ノード・ポート・ライン・配線補助設備に関する詳細仕様をまとめる。
工場ノード / ライン関連の具体仕様については `GAME_DESIGN.md` の概要より本書を優先する。

ただし、**開発段階の採用範囲については `GAME_DESIGN.md` のMVP検証計画を優先する**。
本書における「基本」「初期」は製品版へ向けた基本仕様を意味し、現在のMVPへ一括実装する意味ではない。

実装段階は次のように分ける。

| 段階 | 採用する主な要素 |
| --- | --- |
| 現MVP | 素材源、加工器、合成器、召喚器、DAG配線、固定輸送時間 |
| 中心仮説成立後 | 放射状盤面、固定素材源、ライン長、交差禁止、中継、分配器、切替器 |
| 空間パズル検証後 | 異相門、優先・比率分配、専用バッファ |

現MVPではライン長による魔力消費、分配器、切替器、異相門を実装しない。
後段の機能も、直前段階のプレイテスト基準を満たした後に1群ずつ導入する。

現MVPの工場容量は最大魔力100で固定する。素材源・合成器・召喚器は各20、回転器・移動器・着色器は各15を使用し、
設備削除時に全額を返還する。追加操作と編集確定の両方で上限を検証し、超過グラフを稼働させない。
汎用召喚器は現MVPでは1基に限定し、2基目の追加操作と外部から構成された複数召喚器グラフを確定できないようにする。
編集確定時のグラフ検証は接続操作を経由したことを前提にせず、復元・外部構築されたデータについても、存在しない接続元/先、範囲外ポート、入力重複、通常出力の暗黙分岐、循環を安定順序で拒否する。
復元データではDictionaryキーと設備/ライン内部IDの一致も必須とする。素材源の素材IDと正の生成間隔、加工器の正の処理時間、1〜3段階の回転、整数ベクトルの移動量、空でない着色IDをtick開始前に検証し、不正設定を暗黙補正して稼働させない。
検証エラーは「配線を確認」の一文へまとめず、未接続、循環、入力重複、暗黙分岐、欠損ライン、各設備の不正設定を修正可能な日本語へ変換する。最優先の同じ理由を32秒生産予測と戦闘開始・編集確定の拒否表示で共有する。
ライン接続時は呼び出し元オブジェクトを直接保持せず、ID、端点、ポート、輸送時間、輸送進捗、payloadを所有コピーする。接続後の外部変更で検証済みグラフが変質せず、状態複製と再配線ロールバックでも輸送中Glyphを共有しない。
ラインの所有コピー前にライン存在・IDとpayloadのGlyph構造を検証する。循環・不正子を含むpayloadは位置付き理由とともに拒否し、部分接続を残さない。
設備追加時もID、種類、設定、処理進捗、全バッファを所有コピーし、追加元オブジェクトの後続変更から工場状態を隔離する。コピー前に全仕掛品Glyphを検証し、不正値を含む設備は部分登録せず拒否する。以後の意図的な設備変更は工場が保持する設備をIDで取得して行う。
設備登録は空・重複IDと入力・処理中・出力の不正Glyphを安定順序で集約して返す。登録可否だけの真偽値へ理由を失わず、UI追加失敗や復元処理が同じ診断結果を利用できるようにする。
復元された設備の入力・処理中・出力バッファとラインpayloadは、位置の安定順でGlyph構造を検証する。非Glyph値、不正文法、循環・不正子を検出した場合は32秒予測と開始拒否へ同じ仕掛品破損理由を出し、直接tickが呼ばれても時刻を進めず位置付きエラーを保持する。仕掛品の廃棄後にのみtickを再開する。
不正仕掛品で停止した工場から編集へ入る場合は、深いコピーより先に不正な設備スロット・ラインpayloadだけを廃棄し、有効な仕掛品は保持する。自動廃棄数を累積廃棄へ加算して復旧理由を表示し、その後の編集プレビューとキャンセルは有効仕掛品を通常どおり扱う。
工場状態の非破壊複製は深いコピーの前に、全仕掛品と登録済みレシピを位置付きで再検証する。不正状態では部分コピーを返さず、元状態も変更せずに複製失敗理由を返す。32秒予測、編集開始、Undo保存はこの結果を確認してから複製状態を使用する。

現MVPの再構成トランザクションは、設定変更・再配線時に既存の仕掛品をすべて廃棄候補とする安全側の近似を採用する。
確定前に個数、加工状態別の種類、仕掛品が存在する設備・ラインを表示し、Undoまたはキャンセルでは完全に元へ戻す。
下流の `expectedGlyphStructure` を再推論して影響範囲だけを廃棄する方式は、工場規模を拡張する段階で導入する。

稼働中はライン中央の矢印で流向を表示する。到着先の入力満杯、設備の出力閉塞、合成器の片側素材不足は
別々の診断コードとして保持し、ライン・設備の警告色と盤面下部の文言へ反映する。

## 1. 工場盤面の基本構成

### 1.1 初期配置

工場盤面は、**中央に召喚器を配置し、その周囲に素材源を配置した放射状の構成**を基本とする。

```text
        [素材源]

[素材源]      [素材源]

        [召喚器]

[素材源]      [素材源]

        [素材源]
```

プレイヤーは外周の素材源から中央の召喚器へ向かって、加工器・合成器・補助設備・ラインを配置してグリフの生産経路を構築する。

### 1.2 盤面拡張

- ゲーム開始時の工場盤面は比較的小さい
- ステージクリアやラン進行に応じて、利用可能な盤面領域が少しずつ外側へ拡張する
- 新しい素材源や配置余地が増えることで、より複雑な高位シジル用ラインを構築できるようにする
- 工場全体が中心へ収束する巨大な魔導回路 / 魔法陣のように見えることを狙う
- 初期実装では均等に外側へ広がる方式を基本とし、方向を選ぶ拡張は将来候補とする

## 2. ノードの基本UI

### 2.1 方向非依存ノード

一般的な「左入力 / 右出力」のノードUIは採用しない。

ノード自体は特定方向を持たず、上下左右・斜めを含め、どの方向から接続しても入力 / 出力を識別できる形にする。

ノード形状は横長矩形より、**円形または小型の魔導装置**を基本候補とする。

### 2.2 入力 / 出力ポート

入力と出力は色ではなく、**形状の違い**で常時識別できるようにする。

理由:

- 属性色とUI色の競合を避ける
- 白線主体のアートでも判別できる
- 色覚差に依存しない

候補:

- 入力: 受け口 / 凹形 / 内向き記号
- 出力: 放出口 / 突起 / 外向き記号

具体的な字形はアート検証で決定する。

### 2.3 ポート位置

ポート位置をプレイヤーが手動調整する操作は持たせない。

- ライン接続方向に応じて、ノード外周の適切な位置へ自動配置する
- ノード自体を回転してポート方向を合わせる操作は不要とする
- 接続状態が変わった場合も、可読性を保つ範囲でポート位置を自動調整してよい

これにより、戦闘中の時間停止編集でも素早く再配線できるようにする。

### 2.4 接続操作

- 出力からドラッグして入力へ接続する操作を基本とする
- 接続操作中は接続可能な入力ポートのみ強調表示する
- 出力同士、入力同士、型不一致などの無効な接続は確定できない
- 接続前に直線ラインと必要魔力をプレビューする

### 2.5 基本ポート数

初期仕様は以下を基本とする。

| ノード | 入力 | 出力 |
| --- | ---: | ---: |
| 加工器 | 1 | 1 |
| 合成器 | 2 | 1 |
| 中継ノード | 1 | 1 |
| 分配器 | 1 | 2 |
| 切替器 | 1 | 2 |
| 召喚器 | 多入力 | なし |

召喚器の入力上限は、初期候補として **8入力程度** を想定し、盤面密度を見て調整する。

## 3. ライン

### 3.1 直線接続

通常ラインは、**接続した2ノード間を常に1本の直線で結ぶ**。

```text
[素材源] ───────── [加工器]
```

プレイヤーがライン自体を曲線・折れ線として編集する操作は持たせない。
ライン形状はノード配置だけから決まる。

この方式により、工場編集の基本操作を以下に絞る。

```text
ノードを配置
  ↓
ノード同士を接続
  ↓
直線ラインが生成
```

### 3.2 基本ルール

- ラインはノード間を接続し、グリフを輸送する
- ラインは盤面上の空間を占有する
- 通常ライン同士の重複・交差は禁止する
- 通常ラインは他ノード本体とも交差できない
- 1本のライン上には複数種類のグリフを混在させない
- 前方が詰まった場合は後続グリフも停止する
- ライン長に応じて工場用魔力を使用する
- ライン削除時には使用魔力が戻る
- 工場グラフは有向非循環グラフ（DAG）に限定し、循環を作る接続は確定できない
- 通常ノードの1出力から複数ラインへ直接接続できず、分岐には分配器または切替器を使用する
- 各入力ポートへ接続できるラインは1本だけとする

「1本のライン上には複数種類のグリフを混在させない」は、ラインごとに現在の上流設定から導出した
`expectedGlyphStructure` を持つことで保証する。生産由来情報だけが異なり、正規化構造が同一のグリフは同じ種類として扱う。
構造が一致しないグリフはラインへ投入できず、通常稼働中に暗黙の廃棄は行わない。

### 3.3 流れる方向の表示

入力 / 出力ポートだけでなく、ライン自体にも流向を表示する。

- 静止時: 小さな矢印や方向マーカーをライン上へ表示
- 稼働時: 実際にグリフが移動することで流向を視覚化

ポート形状、ライン方向表示、グリフ移動の3段階で、どの向きに流れているかを理解できるようにする。

### 3.4 グリフの配置と詰まり

- ライン上には複数グリフが一定間隔で実際に並んで流れる表現を基本とする
- 前方が停止した場合は、その後ろのグリフも順番に停止する
- 見た目から詰まり箇所と流量を把握できることを優先する
- 具体的な間隔、速度、ライン容量はプロトタイプで決定する

### 3.5 ポート配置と交差判定

接続・切断・ノード移動のたびに、仮編集グラフ全体について次の順序で幾何状態を再計算する。

1. 各ノードの接続先を角度順に並べる。同角度の場合はラインID順とする
2. その安定順序からノード外周のポート位置を確定する
3. 確定したポート間に直線セグメントを生成する
4. ライン同士、ラインとノード本体、盤面境界との交差を検証する

判定規則:

- 同じノードへ正しく接続するライン端点だけはノード境界との接触を許可する
- 接続関係のないライン同士の交差、接触、同一直線上の重複は禁止する
- 接続先ではないノードの境界・内部への接触は禁止する
- 中継ノードを共有する2本のラインは、その中継ノード上の端点接触だけを許可する
- 異相区間は通常ラインとの交差検証対象から除外する

無効な状態は赤いプレビューと理由を表示し、編集トランザクションを確定できない。
既存の確定済みグラフを自動で変形・切断して解決せず、最後に有効だった仮編集状態へ戻せるようにする。

## 4. 中継ノード

### 4.1 目的

通常ラインは必ず直線であるため、障害物や別ラインを避けて迂回したい場合は、**中継ノードを配置して直線を複数本に分ける**。

```text
[素材源] ─── [中継]
                  \
                   \
                  [加工器]
```

### 4.2 ルール

- 1入力 / 1出力
- グリフを加工しない
- グリフの種類を変更しない
- 処理時間を持たない
- 配線経路を作ることだけが役割
- 中継ノード自体の魔力コストは無料またはごく低コストを第一候補とする
- 中継によって総ライン長が増えた分の魔力コストは通常通り発生する

ライン上に不可視の制御点を置くのではなく、中継位置も盤面上の明示的な要素として可視化する。

## 5. 初期の配線補助設備

初期の補助設備は増やしすぎず、以下を基本セットとする。

| 補助 | 役割 |
| --- | --- |
| 中継ノード | 直線ラインを複数本に分けて迂回経路を作る |
| 分配器 | 1入力を複数出力へ順番に振り分ける |
| 切替器 | 複数出力のうち1つだけを選んで流す |
| 異相門 | ラインを一時的に別位相へ通し、他ラインを跨ぐ |

---

## 6. 分配器

### 6.1 基本動作

1本の入力ラインから受け取ったグリフを、2本の出力ラインへ振り分ける。

**グリフを複製する設備ではない。**

初期仕様はラウンドロビンを基本とする。

```text
               ┌→ 出力A
入力 → [分配器]
               └→ 出力B

1個目 → A
2個目 → B
3個目 → A
4個目 → B
```

### 6.2 出力が詰まった場合

通常のラウンドロビン順は維持するが、次の出力が受け取り不能な場合は、**送れるもう一方の出力へ送る**。

```text
A: 詰まり
B: 空き

→ Bへ送る
```

片方の出力閉塞だけで分配器全体が停止する状態を避ける。
両方の出力が受け取れない場合のみ停止する。

ラウンドロビンポインタは、**実際に送信できた出力の次**へ進める。
優先予定だったAが詰まりBへ送った場合、次回はAから試す。両方が詰まって送信できなかったtickではポインタを進めない。
これにより、閉塞解除後に飛ばされていた出力を先に再試行し、同じ入力列から常に同じ分配結果を得る。

### 6.3 用途

同じ中間グリフを、低位シジル召喚と高位シジルの追加加工へ分ける用途などを想定する。

```text
素材源
  ↓
加工器
  ↓
分配器
 ├→ 低位シジル → 召喚器
 └→ 追加加工 → 高位シジル → 召喚器
```

これにより、生産能力をどこへ配分するかという判断を作る。

## 7. 切替器

### 7.1 基本動作

1本の入力に対して2本の出力候補を持ち、**選択されている1系統にだけグリフを流す**。

```text
               ┌→ ラインA
入力 → [切替器]
               └→ ラインB
```

分配器との違い:

- 分配器: 複数ラインを同時運用する
- 切替器: その時点では1つのラインだけを運用する

### 7.2 戦況対応

出力先の変更は**時間停止中のみ**可能とする。

```text
基本グリフ
  ↓
切替器
 ├→ 大型化ライン → 大型召喚獣
 └→ 別加工ライン → 群体召喚獣
```

通常戦闘中に即時切替できるようにはせず、時間停止 / 再構成システムの一部として扱う。

戦況を見て毎回ラインを撤去するだけでなく、**将来の切替を見越した工場を事前設計する**というプレイヤースキルを作る。

## 8. 異相門（仮称）

### 8.1 目的

通常ラインの交差禁止を維持しつつ、どうしても越えられない既存ラインを跨ぐための特殊設備。

一般的なコンベアゲームの地下ベルトに相当するが、世界観上は**一時的に別位相へグリフを送る**表現とする。

```text
通常ラインA
────────────────

ラインB
── [異相門入口] ··· [異相門出口] ──
```

### 8.2 入口 / 出口の一括配置

異相門は入口と出口を別々の設備として購入・配置するのではなく、**入口と出口のペア全体を1つの設備として配置する**。

操作例:

```text
異相門を選択
  ↓
入口位置を指定
  ↓
出口位置を指定
  ↓
1つの異相門として確定
```

内部的にも1オブジェクトとして扱う。

```text
PhaseGate {
  entrance
  exit
}
```

これにより複数の異相門を置いた場合でも、どの入口と出口が対応しているかを明確にする。

### 8.3 魔力コスト

- 入口 / 出口それぞれに別料金を設定しない
- **1ペア全体に対して1つの固定魔力コスト**を設定する
- 必要であれば、異相距離に応じた追加コストを別途検討する

### 8.4 基本制約

- 1異相門 = 入口1 + 出口1の固定ペア
- 異相区間は通常ラインとの交差判定を無視する
- 異相区間同士の交差も許可する
- 異相区間の途中では分岐できない
- 異相区間の途中へ加工器・合成器・補助ノードを配置できない
- 中間地点から出入りできない
- グリフは入口から入り、対応する出口から同一状態で出る
- 最大距離を設けるかは盤面サイズと実際の使用感を見て決定する
- 異相区間は入口バッファ、輸送中キュー、出口バッファを持つ1本の輸送路として扱う
- 輸送時間は最低1tickとし、同一tickに入口から出口へ即時通過しない
- 輸送中キューの順序はFIFOとし、出口が詰まった場合は入口側へ閉塞が伝播する

異相門は通常配線より便利だが、すべてを異相門で接続することが最適にならないコスト設定を行う。

### 8.5 表現

- グリフが入口で消え、出口から再出現する
- 入口 / 出口は魔術的な門・裂け目・環として表示する
- 入口と出口の対応は薄い点線、残像、固有マーカーなどで確認可能にする
- 対応表示には属性色との競合を避けるため、色だけに依存しない

## 9. ノードのバッファと閉塞

### 9.1 出力バッファ

通常設備は、処理完了後のグリフを**出力側に1個だけ保持できる**ことを基本とする。

```text
入力
 ↓
加工
 ↓
完成グリフ
 ↓
出力ラインが詰まっている
 ↓
ノード内に1個保持
 ↓
設備停止
```

保持中は次のグリフ処理を開始しない。

### 9.2 閉塞の伝播

- 出力バッファが埋まる
- 設備が停止する
- 入力側が受け取れなくなる
- 上流ラインも順番に詰まる

という挙動を基本とする。

詰まりをファクトリーゲームの読み取れる状態として視覚化する。

### 9.3 固定tickの処理順

同じ工場状態と入力から常に同じ結果を得るため、1tickの更新順序を固定する。

1. tick開始時点のノード、ライン、バッファの受入可能状態をスナップショットする
2. 処理時間を満たした設備の出力候補を確定する
3. 送信要求を `送信元ノードID → 出力ポート番号 → ラインID` の安定順序で並べる
4. スナップショットを基準に出力先を予約し、分配器などの送信先を決定する
5. 予約済みの移動を一括反映する
6. 成功した送信についてバッファ、処理状態、分配器ポインタを更新する
7. 次tickに向けて閉塞・プレビュー表示を更新する

同一tick中に先に処理された設備の結果を、後続設備がそのtick内でさらに転送することはない。
tick開始時に満杯だった入力や使用中だったラインは、同tick内の消費・到着で空いても次tickまで新しい搬入・送信へ再利用しない。
このスナップショット理由で実際に拒否されたラインID・出力ノードIDはtick結果として保持し、終了時点で空きが生じていても入力満杯・出力閉塞の警告を消さない。
盤面の警告文は瞬間的な閉塞でも読めるよう最低5tick（現MVPでは1秒）保持するが、ライン・設備の警告色は古い状態を残さず現在の診断だけを反映する。
設備内とライン輸送中の有効Glyphは、汎用ドットではなく完成シジル見本と同じPrimitive・色・回転・合成外周の縮小表示で描く。設備は出力、処理中、入力の順で代表仕掛品を表示し、工程ごとの構造変化を盤面上で追えるようにする。不正Glyphは描画せず既存の破損診断を優先する。
複数入力設備では各入力ポート直内側へ対応Glyphを個別表示し、入力順と不足側を判別可能にする。処理中・出力Glyphは設備下部へ分離し、合成前の素材と合成後の構造を同時に混同しないようにする。
召喚器へ直接向かう輸送中Glyphだけは、副作用なしの実召喚と同一レシピ判定を到着前に行い、完全一致を緑、不一致を赤の外周で示す。中間ラインには成否色を付けず、未完成素材を誤って失敗扱いしない。判定表示によって召喚イベントや廃棄数を変更しない。
素材源の生成tickと加工器の残り処理tickは、設備上端の短い進捗バーとして表示する。完成出力を保持中は100%を示し、待機中の加工器と瞬時判定の召喚器にはバーを出さない。閉塞は進捗色ではなく既存の赤枠を優先し、稼働・待機・完成・閉塞を視覚的に分離する。
32秒非破壊予測では召喚数だけでなく、各設備・送出ラインで最初に確認できた出力Glyphを所有コピーで採取する。実仕掛品がない設備には予測出力を半透明で表示し、素材源から回転・着色・合成後までの構造変化を戦闘前から追えるようにする。実仕掛品が存在する場合は実表示を優先し、無効グラフでは予測ゴーストをすべて消す。
縮小Glyphは単体Primitiveを読み取れる大きさまで拡大し、Combineは外周が設備枠へ収まる別縮尺を使用する。予測ゴーストは形・色・回転を判別できる透明度を保つ。戦闘前かつ進捗0%の空バーは表示せず、未稼働設備に黒い線だけが残らないようにする。
設備IDとラインIDはセーブ・ロード後も変わらない安定IDを使用し、画面上の配置順やDictionaryの走査順へ依存しない。

## 10. 工場編集時の仕掛品

- 時間停止中にラインやノードを仮削除しても、確定するまでは元状態を保持する
- 編集確定時に削除されたライン上・設備内に存在していたグリフは廃棄する
- 廃棄されるグリフの数・種類は確定前に表示する
- 魔力は設備 / ライン削除に応じて戻るが、廃棄された仕掛品は素材へ戻さない

設定変更や再配線によってラインの `expectedGlyphStructure` が変わる場合は、削除されていないラインも含めて型を再推論する。
確定前に、新しい期待構造と一致しない仕掛品を次の範囲から廃棄対象として列挙する。

- 設定を変更したノードの入力・処理中・出力バッファ
- 期待構造が変わる下流ライン上のグリフ
- 入力の期待構造が変わる下流ノードのバッファと処理中グリフ

再推論は召喚器、または構造が変更前後で同一になる地点までDAGの下流へ伝播する。
対象数、種類、影響ラインを確定前に表示し、編集キャンセル時は元の仕掛品を完全に復元する。
これにより、設定変更後も1ライン1種類を維持し、古いグリフと新しいグリフが暗黙に混在しないようにする。

これにより大規模な再構成には生産上の小さな損失が生じるが、編集操作そのものには追加通貨を要求しない。

## 11. 後から追加する補助設備候補

以下は初期セットには含めず、必要性が確認された場合やローグライトの上位設備として追加を検討する。

### 11.1 優先分配器

```text
               ┌→ 優先ライン
入力 → [優先]
               └→ 余剰ライン
```

- 優先出力が受け取れる限り、そちらへ送る
- 優先出力が詰まった場合だけ、もう一方へ送る

例: 高位シジル生産を優先し、余った中間グリフだけ低位召喚へ回す。

### 11.2 比率分配器

出力比率を指定できる分配器。

候補:

```text
50 : 50
75 : 25
100 : 0
```

通常分配器より理解・調整項目が増えるため、最初からは導入しない。

### 11.3 バッファ

複数個のグリフを意図的に一時保管する専用設備。

```text
素材 → 加工 → [バッファ] → 加工
```

通常設備の1個出力バッファとは別物とする。

戦況変化時に蓄積した中間グリフを切替ラインへ流すなどの戦術が可能になるが、物流ゲーム寄りの管理要素が強くなるため、中心ループで必要性が確認されてから追加する。

## 12. 原則として導入しない設備

### 12.1 通常の合流器

物流だけを目的とした複数入力 → 1出力の合流器は、原則として導入しない。

理由:

- 複数グリフを1グリフへまとめる意味のある処理はすでに**合成器**が担う
- 合流と合成の違いが分かりづらくなる
- 1本のラインへ複数種類のグリフを混在させないルールと衝突しやすい

### 12.2 通常の複製器

入力グリフ1個を複数個へコピーする通常設備は導入しない。

```text
A → 複製 → A + A
```

を自由に行えると素材源の生成速度や分配判断の意味が弱くなるため。

特殊なリリック・能力・高コスト設備として例外的に導入する余地は残す。

---

## 13. 補助設備の設計原則

- 加工器 / 合成器 / 召喚器が工場の主役であり、補助設備を増やしすぎない
- **1ノード1機能**を基本とする
- 分配器は分ける、切替器は選ぶ、異相門は跨ぐ、という役割を混ぜない
- 高度な物流挙動は万能ノード1個ではなく、複数ノードの組み合わせで作ることを基本とする
- 補助設備は「物流を自動化するため」より、**空間制約と戦況対応に選択肢を作るため**に導入する
- ライン交差禁止は重要なパズル制約として残す
- 異相門などの回避手段は、交差禁止を無意味にしないコスト / 制約を持たせる
- 将来の敵構成を予測して、分配器・切替器を含む柔軟な工場を設計する価値を作る
- 補助設備を使わず、単純な短いラインを作ることにも魔力・面積効率上の価値を残す
