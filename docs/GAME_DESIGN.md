## 1. 概要

**Sigil Factory** は、シジルを構成するグリフを工場で加工・合成し、完成したグリフを召喚器へ送り、対応する召喚獣を戦場へ継続的に送り出して戦う **ファクトリー × RTS × ローグライト** ゲーム。

ゲームの中心は、単に召喚獣を選択することではなく、**所持しているシジルを実際に生産できる工場を構築し、戦況に応じて工場を組み替えること**に置く。

基本ループは以下。

```text
ルート選択
  ↓
ステージ情報を確認
  ↓
工場を構築
  ↓
リアルタイム戦闘
  ↓
必要に応じて時間停止
  ↓
工場・召喚門を再構成
  ↓
戦闘再開
  ↓
敵リーダー撃破
  ↓
シジル・リリック・能力などを獲得
  ↓
次のルートへ
```

## 2. ゲームの柱

### 2.1 シジルを「レシピ」ではなく工場で実際に作る

シジルごとに必要な図形構造があり、素材から加工・合成して対応する形のグリフを作る。

召喚器へ送られたグリフ全体が、所持しているシジルのいずれかと完全一致した場合、そのシジルに対応する召喚獣が戦場へ召喚される。

プレイヤーがシジルの形を知っていても、**そのランでシジル自体を取得していなければ召喚できない**。

### 2.2 低位シジルから高位シジルへ発展する

高位シジルは、低位シジルの構造を応用・発展させた形にする。

```text
低位シジル
    ↓
既存の加工工程
    ↓
低位相当のグリフ
    ↓
追加加工・追加合成
    ↓
高位シジル
```

基本的には高位シジルを作成した方が強くなるバランスとする。

一方で、リリックによって、低位シジル大量召喚・短工程シジル・特定形状などを強化し、例外的なビルドが成立する余地を作る。

### 2.3 戦況を見て工場を組み替える

戦場はリアルタイムで進行する。

プレイヤーは時間停止ゲージを使用して時間を止め、その間に工場や召喚門を変更できる。

「戦闘前に正解の工場を作って終わり」ではなく、戦況・シジル進化・前線の変化などによって戦闘中にも工場を変更する理由を作る。

## 3. 用語

| 用語 | 定義 |
| --- | --- |
| 素材 | グリフを構成する基本的な記号部品。単純な幾何学を骨格にしつつ、見た目は魔術的なルーン部品にする |
| 素材源 | 素材を一定周期で供給する固定設備 |
| グリフ | 工場内をライン上で流れる加工対象。複数素材を合成して1グリフにできる |
| 加工器 | 拡大・縮小・回転・移動・着色など、入力グリフを変換するノード |
| 合成器 | 複数グリフを1つのグリフへ合成するノード |
| ライン | ノード間を接続し、グリフを輸送する経路。盤面上の空間を占有する |
| シジル | 召喚獣に対応する、取得可能な完成図形パターン |
| 召喚器 | 工場側の汎用判定設備。入力されたグリフを所持シジルと照合する |
| 召喚門 | 戦場側の召喚獣出現地点。時間停止中に自陣内で移動可能 |
| 召喚獣 | シジル判定成功時に戦場へ出現する自軍ユニット |
| リーダー | 自軍の敗北条件となるユニット |
| 敵リーダー | 撃破するとステージ勝利となる敵ユニット |
| リリック | ラン中に獲得する、ルールやビルドを変化させる強化要素（仮称） |

## 4. 工場システム

### 4.1 基本構造

純粋なコンベア方式ではなく、**ノードで加工し、空間を占有するラインで輸送する方式**を採用する。

```text
[素材源] ═══ [加工器] ═══ [合成器] ═══ [召喚器]
              ↑
        ライン上をグリフが流れる
```

ノードグラフの操作性を持たせつつ、ラインの配置・長さ・交差制約を持たせることで、ファクトリーゲームとしての空間パズルを残す。

### 4.2 稼働ルール

- 素材源から一定周期でグリフが生成される
- グリフはライン上を目に見えて移動する
- 召喚器へ到着した時点でシジル判定を行う
- 所持シジルと一致した場合は対応する召喚獣を召喚する
- 一致する所持シジルがない場合、グリフは消滅する
- 1本のライン上には複数種類のグリフを混在させない
- ライン前方が詰まった場合は後続も停止する
- 通常ラインは1入力1出力を基本とする
- 分岐には専用の分岐器を用いる
- 通常の合流は行わず、複数グリフをまとめる場合は合成器を使用する

### 4.3 ライン

- ラインは盤面上の空間を占有する
- ライン同士は重ならない / 交差しない
- 長さに応じて工場用の魔力を使用する
- 削除すると使用していた魔力は戻る
- グリフの見た目上の大きさと、ライン上での物流占有サイズは分離する

### 4.4 素材源

- 素材源は固定配置
- 無限に素材を生成する
- 素材源ごとに生成速度が異なる

### 4.5 加工器

想定する基本加工:

- 拡大
- 縮小
- 回転
- 移動
- 着色

加工器は、**入力された1グリフ全体に対して作用する**。

例: 複数素材を合成済みのグリフに赤色変換をかけた場合、グリフ全体が赤くなる。

### 4.6 合成器

- 複数グリフを1グリフとして合成できる
- 素材同士は重なってよい
- 合成後は全体を1グリフとして扱う
- グリフ全体の基準座標は中央 `(0, 0)`
- 合成時は各入力グリフの中心座標を重ねる
- 任意の位置関係を作りたい場合は、合成前に移動加工を行う

```text
グリフA      グリフB
   ○            □
 (0,0)        (0,0)

       ↓ 合成

      ○□
      ↑
   同じ中心基準
```

### 4.7 召喚器

召喚器はシジルごとの専用品ではなく、**汎用召喚器**とする。

- 1つの召喚器に複数ラインを接続可能
- 各ラインから異なる種類のグリフを送れる
- 到着したグリフごとに所持シジル一覧と完全一致判定する
- 部分一致は認めない
- 高位シジル内に低位シジルの形が含まれていても、グリフ全体が低位シジルと一致しなければ低位召喚は発生しない
- 召喚器は対応する戦場側の召喚門へ召喚結果を送る

現時点では **1召喚器 ↔ 1召喚門** を基本とする。

## 5. 工場リソース

### 5.1 魔力

魔力は「消費通貨」ではなく、**工場の構築容量**として扱う。

- ノード配置時にノード価格分の魔力を使用する
- ノード削除時に使用魔力は戻る
- ラインは長さに応じて魔力を使用する
- ライン削除時に使用魔力は戻る

```text
最大魔力: 100
使用魔力: 72
空き魔力: 28
```

最大魔力はローグライト強化対象にしてよい。

### 5.2 時間停止 / 再構成チャージ

工場用魔力とは分離する。

時間停止は、プレイヤーの思考速度ではなく、**戦闘中に工場を再構成する判断のタイミング**を制約する仕組みとする。

- 時間停止中は工場・戦場とも完全停止する
- 時間停止中のみ工場編集と召喚門移動を行える
- 思考時間や仮編集の回数にはコストを課さない
- 編集内容は再開時に一括確定する
- 最初の統合プロトタイプでは停止回数を制限せず、再構成したくなる状況が自然に生まれるかを先に検証する
- 有限化する場合は、停止開始時に固定チャージを消費し、通常戦闘中に回復する方式を第一候補とする
- 変更量コストや再起動遅延は、無制限の全面換装が最適化した場合のみ追加検討する

これにより、工場容量と再構成機会を分けつつ、UI操作速度や熟考そのものを罰しない。

## 6. 戦場システム

### 6.1 基本方針

製品版の戦場は、複数の進軍経路と位置関係を把握できる**見下ろし型の2Dマップ**とする。
横一列に押し合うサイドビューを最終形にはしない。戦場はRTS風とするが、細かなマイクロ操作を主役にはしない。

段階1のMVPだけは、工場出力と前線反転の因果を最小コストで検証するため、戦場を一本道へ抽象化する。
この1レーン表示は戦闘モデルの仮実装であり、製品版のカメラ・地形・移動仕様を確定するものではない。

召喚獣は基本AIで行動し、プレイヤーが出せる命令は大まかなものに限定する。

初期候補:

- 前進
- 防衛
- 集合
- 指定地点へ移動

完全待機によって無制限に兵力を貯めるだけの戦術が最適化しないよう、命令下でも周囲の敵には反応するなどの設計を検討する。

### 6.2 勝敗条件

- 敵リーダー撃破 → 勝利
- 自軍リーダー撃破 → 敗北

### 6.3 召喚門

- 工場側の召喚器から送られた召喚獣が出現する地点
- 時間停止中のみ移動可能
- 自陣の範囲内でのみ配置可能

前方へ出すほど前線へ到着しやすいが、危険になるような戦術性を持たせる。

### 6.4 敵召喚門と自陣拡大

- 敵召喚門は破壊可能
- 敵召喚門を破壊すると、その周辺を自陣として獲得する
- 自陣が広がることで、自軍の召喚門をさらに前方へ移動可能になる

```text
敵召喚門を破壊
  ↓
敵の召喚能力低下
  ↓
自陣拡大
  ↓
召喚門を前進
  ↓
さらに奥を攻略
  ↓
敵リーダー撃破
```

### 6.5 敵側のルール

最初の実装では、敵側に工場シミュレーションを持たせない。

敵召喚門から、ステージ設定に基づいて敵ユニットを生成する。

ただし理不尽に見えないよう、出現予定・次回召喚までの時間などをプレイヤーが予測できる表現を検討する。

### 6.6 ステージ地形

ステージごとに地形を変える。

例:

- 狭路
- 川
- 崖
- 高台
- 沼
- 森林
- 障害物

地形によって大量召喚・大型・遠距離・飛行・高速・攻城などの有効性を変える。

### 6.7 召喚獣の生存

- 死亡時は即消滅
- 同時存在数にゲームルール上のハード上限は基本的に設けない
- 弱い召喚獣の大量生産も正当な戦術として残す

大量生産を上限で抑えるのではなく、地形・前線・範囲攻撃・攻城能力などで有効性を変化させる。

## 8. ローグライト進行

### 8.1 ルート選択

よくある分岐型ルートマップを採用する。

```text
開始
  ↓
  ├─ 通常戦闘 ─┐
  │             ├─ 強敵 ─ イベント ─ ボス
  └─ 別戦闘 ───┘
```

ステージ候補ごとに地形・敵・報酬傾向などを確認し、現在のビルドと今後欲しい強化を考えて進路を選択する。

### 8.2 シジル獲得

- 所持シジルはラン中に増えていく
- 未取得シジルは形を知っていても召喚不可
- 高位シジルは前提となる低位シジルを所持していないと報酬候補に出現しない

### 8.3 シジル進化

ステージクリアなどで共通進化ポイントを獲得し、所持シジルへ任意に割り振る。
一定値に達した際は、そのシジルから派生する上位候補2つから1つを取得する。
実際に召喚したシジルには追加進化ボーナスを与えるが、召喚数を進化の必須条件にはしない。

```text
低位シジル
  ↓ 共通進化ポイントを割り振る
上位候補A / 上位候補B
  ↓ 選択
さらに上位へ
```

高位シジルほど複雑な工場ラインを要求する。

進化候補は、現在所持している素材・加工器で製造可能なものを優先して提示する方向を検討する。

### 8.4 ラン中に獲得・強化できるもの

基礎リソースは少数に保つ一方、ローグライトの強化候補は豊富にしてよい。

候補:

- 新しい素材
- 新しい加工器
- 新しいシジル
- 最大魔力
- リリック
- ラインコスト軽減
- 特定加工器コスト軽減
- 素材生成速度強化
- ライン速度強化
- 時間停止ゲージ最大値
- 時間停止ゲージ回復速度
- 特定シジル系統強化
- 特定形状・色・加工工程を参照する特殊強化
- 低位シジル強化
- 大量召喚型強化
- 少数精鋭型強化

重要なのは、単純な数値上昇だけでなく、**取得すると工場の最適構成そのものが変化する強化**を多く用意すること。

例:

- 加工工程が少ないシジルを強化
- 合成器を通ったグリフから召喚されたユニットを強化
- 特定色を含むシジルに追加効果
- 低位シジルを一定数召喚するたび追加効果

## 9. シジル設計方針

### 9.1 基本方針

単なる `○ / △ / □` のパズルに見せるのではなく、単純な幾何学を骨格にした**独自の魔術記号 / ルーン部品**としてデザインする。

候補となる部品イメージ:

- 環
- 弧
- 直線
- 鉤
- 枝
- 棘
- 点
- 菱形
- 結界状の枠

システム上は単純で加工しやすく、見た目は魔術的にする。

### 9.2 シジル文法

ユーザーが未知の上位シジルを見ても、ある程度結果を予測できる規則性を持たせる。

例として以下のような役割分担を検討する。

- 形状 / 部品 → 性質・役割
- 色 → 属性
- 大きさ → 規模・大型化
- 個数 / 複製 → 数・分裂
- 配置 → 挙動や派生

ただし文法を増やしすぎず、最初は3〜4程度の強い規則から始める。

高位シジルは低位シジルの骨格を残し、発展関係を視覚的に理解できるようにする。

これによりプレイヤーが、将来の進化を予測して工場内に拡張余地を残すなどの計画を立てられるようにする。

## 10. アートスタイル

### 10.1 基本コンセプト

**黒い魔術書 / 魔導回路**を基調とする。

- 黒〜非常に暗い背景
- 白い細線・幾何学線
- ドット状 / 粒子的な発光
- 属性など意味のある要素だけに色を使う
- 魔術書、錬金術図、星図、魔法陣、電子回路を混ぜた印象
- 「古代魔術なのか機械なのか分からない」雰囲気

完全なレトロピクセルアートではなく、ベクター的な線を低解像度感・ドット発光で表現する方向。

### 10.2 工場・戦場

工場は巨大な魔導回路のように見せる。

完成した工場全体が、俯瞰すると巨大な術式 / 魔法陣に見えるのが理想。

戦場もリアルな地形表現ではなく、魔術師が見ている戦術盤・地図記号のような抽象表現を検討する。

### 10.3 ローグライト / メタUI

魔術書モチーフをより強く使う。

- シジル図鑑
- シジル進化選択
- リリック
- ルートマップ

黒い紙に白インク、必要に応じて金・赤・属性色を差し色として使う。

### 10.4 可読性

黒背景＋白線では全要素が同じ強さに見えやすいため、以下は視覚階層を明確に分ける。

- 静的設備
- ライン
- 流れているグリフ
- 選択中オブジェクト
- 敵 / 危険
- 属性
- 召喚成功

## 11. 現在の設計上の懸念

### 11.1 高位シジルが単なる増築にならないか

高位シジルが常に「既存ラインの末尾を少し延ばすだけ」になると、工場パズルが単調になる。

上位進化によって別素材源との合成、迂回、新しい加工器などが必要になり、既存工場を活かしつつ再設計を要求する余地を作る。

### 11.2 前線の永久膠着

自軍・敵軍とも継続的に召喚されるため、同程度の戦力では中央で永久にぶつかり続ける可能性がある。

解決手段として、範囲攻撃・攻城・高速突破・飛行・押し出し・敵召喚門破壊など、膠着を崩せる役割を用意する。

### 11.3 時間停止ゲージ待ち

通常時間中にゲージが自然回復するため、安全な状態を作って待つことが最適行動になる可能性がある。

まずは単純な自然回復で試し、実際に問題が起きた場合のみ回復条件を追加する。

### 11.4 召喚器周辺の配線集中

汎用召喚器へ複数ラインを集めるため、後半に召喚器周辺が配線で埋まりやすい。

必要に応じて以下を検討する。

- 召喚器を複数置く
- 入力可能方向 / 接続数を拡張する
- 上位召喚器を用意する

### 11.5 工場とRTSの認知負荷

RTS操作を増やしすぎると工場が邪魔になり、工場を複雑にしすぎると戦場を見る余裕がなくなる。

RTS側は大まかな命令に留め、ゲームの中心は工場構築と再構成に置く。

## 12. 検討中の仕様

以下はプロトタイプを通して決める。

- 工場盤面の具体的なサイズ
- グリッド制 / 自由配置の詳細
- ラインの具体的な引き方
- ライン速度
- ライン長が物流時間へ与える影響
- 加工器 / 合成器に処理時間を持たせるか
- 素材源ごとの具体的な生成周期
- 召喚器の最大入力ライン数
- シジル熟練度 / レベルアップ条件
- シジル文法の具体的な規則
- 各召喚獣のロールとステータス
- リリックの具体的な種類とレアリティ
- ショップや通貨を導入するか
- 1ランの長さ / エリア数 / ステージ数

## 13. シミュレーション共通ルール

### 13.1 基本方針

工場と戦場は、同じ時間軸上で決定的に進行するシミュレーションとして扱う。

- シミュレーションは固定tickで更新する
- 同じ初期状態と入力からは同じ結果が得られるようにする
- 描画フレームレートとゲームロジックを分離する
- 時間停止中は工場、物流、戦場AI、攻撃、死亡、占領をすべて停止する
- MVPでは設備接続グラフを有向非循環グラフ（DAG）に限定する
- ラインは空間上で曲げてよいが、接続関係としての循環は禁止する
- 循環的な再加工は、将来必要になった場合に専用設備として追加する

### 13.2 工場設備の状態

各設備は最低限、以下の状態を持つ。

| 設備 | 状態 |
| --- | --- |
| 素材源 | 待機 / 生成可能 / 出力待ち |
| 加工器 | 入力待ち / 処理中 / 出力待ち |
| 合成器 | 入力予約待ち / 処理中 / 出力待ち |
| 召喚器 | 入力待ち / 判定中 / 召喚通知 / 廃棄 |
| ライン | 空き / 輸送中 / 出力閉塞 |

実装前に、ライン容量、アイテム間隔、入力・出力バッファ、処理時間、同時到着時の順序を定義する。

- 出力が詰まった設備は、完成品を出力バッファへ保持して停止する
- 合成器は必要な入力がすべて揃った時点で同時に消費する
- 召喚器の複数入力は決定的なラウンドロビンで処理する
- バッファ満杯、素材不足、出力閉塞は異なる警告として表示する
- 配線時に型の不一致と循環を検出し、不正な接続を確定できないようにする

### 13.3 工場と戦場の時間契約

敵の予告を見てから対処が前線へ届くまでを、以下の合計として扱う。

```text
必要対応時間 =
  編集猶予
  + 素材生成待ち
  + 加工・合成時間
  + ライン輸送時間
  + 召喚処理時間
  + 召喚門から接敵地点までの移動時間
```

確定予告の猶予は、対象となる対抗シジルの必要対応時間以上を保証する。

予告は正確な全個体数を常時見せるのではなく、以下の階層で表示する。

- 20〜30秒先: 敵種、到着時間、経路
- 大きな編成変化: 45〜60秒前に警告
- さらに先: 大群、飛行、装甲、攻城などの曖昧な予兆

再配線だけを唯一の正解にはせず、既存ラインの余剰能力、複数兵種の併産、現行兵種の増産など複数の対処を成立させる。

### 13.4 基準となる計測値

初期調整では最低限、以下を計測する。

- 初回召喚までの時間
- シジルごとの理論 / 実スループット
- 工場の詰まり時間
- 時間停止回数
- 戦況を理由に工場を変更した回数
- 変更確定から前線へ影響が出るまでの時間
- 各シジルの魔力、面積、生産周期あたりの実効戦力
- 同時存在ユニット数とフレームレート

## 14. グリフのデータ表現と一致判定

### 14.1 離散表現

完全一致判定には描画結果や浮動小数点座標を使用しない。

```text
GlyphComponent {
  primitiveId
  xStep
  yStep
  rotationStep
  scaleStep
  colorId
}

Glyph {
  components[]
  localOrigin
}
```

- 位置、回転、倍率、色は有限段階とする
- グリフは固定ローカル原点を持つ
- 移動加工は原点を動かさず、構成部品の座標を変更する
- 合成時は各入力グリフのローカル原点を重ねる
- 同一位置に重なった同一部品も個数を保持する
- 部品の入力順など、ゲーム上意味のない差だけを正規化する
- 回転、倍率、色、部品の相対位置は原則として一致条件に残す
- 回転対称などを許す場合は、シジル側に明示的な対称性属性を持たせる

正規化後のデータを比較し、内部的にはハッシュ一致で判定してよい。

### 14.2 プレイヤー向け診断

召喚失敗時は、不一致という結果だけでなく修正可能な差分を表示する。

優先して表示する差分:

- 不足している部品
- 余分な部品
- 色の違い
- 回転の違い
- 倍率の違い
- 位置のずれ

完成シジルのゴースト表示、工程プレビュー、召喚器到着前の一致見込み表示を検討する。シジル取得後はレシピを常時確認可能とし、暗記テストにはしない。

### 14.3 低位・高位シジルの比較軸

高位シジルは単純な上位互換にしない。以下を同じ表で比較する。

- 初回召喚までの時間
- 定常召喚速度
- 魔力使用量
- 工場面積
- 合成同期の難しさ
- 仕掛品量
- 生産切替速度
- 前線到達速度
- 得意対象
- 過剰火力やカウンターへの弱さ

低位には初動、分散、損失許容、再構成容易性という恒久的価値を持たせる。高位は「常に強い」ではなく「特定状況への解決力が高い」ものとする。

## 15. 時間停止中の編集

### 15.1 編集トランザクション

```text
戦闘中
  ↓
停止開始
  ↓
編集開始時スナップショット
  ↓
ゴースト状態で仮編集・検証
  ↓
変更確定 / キャンセル
  ↓
一括反映して戦闘再開
```

- 仮配置、Undo、キャンセルは無料
- 編集中は変更前の稼働状態を保持する
- 魔力超過、不正配線、循環、ライン交差、孤立ポートがある場合は確定できない
- 削除設備内や削除ライン上のグリフは確定時に廃棄する
- 廃棄される仕掛品の数と種類を確定前に表示する
- 再開時に変更を同時反映し、編集途中の一瞬だけ不正な工場が稼働しないようにする
- 召喚済みユニットや戦場状態は停止中に変化しない

### 15.2 制約の導入順

最初の統合プロトタイプでは無制限停止とし、次を観察する。

1. 戦況を理由に自然と工場を変更するか
2. 全面換装と部分改修のどちらを選ぶか
3. 停止中の操作時間がプレイ時間を圧迫しないか

制約が必要と確認できた場合のみ、以下を一つずつ追加する。

1. 停止開始時の固定チャージ
2. 再停止までの回復時間
3. 大規模変更後の再起動遅延
4. 変更量に応じた再調律コスト

思考時間そのものを課金する方式は採用しない。

## 16. MVP検証計画

### 16.1 検証する中心仮説

> 敵の次の脅威を読み、限られた工場容量を速度・強さ・柔軟性のどこへ振るか決め、既存工場を部分的に組み替えた結果、異なる軍勢が流れ出して前線を反転させる瞬間は、繰り返したくなるほど楽しいか。

### 16.2 段階0: 技術サンドボックス

戦闘を接続する前に、同じ実装を使った短期検証を行う。ここではゲーム全体の面白さを評価せず、操作と理解の問題だけを切り分ける。

- 素材2種類
- 加工器2種類
- 合成器1種類
- シジル3種類
- 離散加工と一致判定
- 詰まり、不一致、削除時の診断
- 完成シジルのゴースト表示
- Undoと工程プレビュー

合格条件:

- 初回完成まで3〜5分以内
- 召喚相当の失敗理由を80%以上のテスターが説明できる
- 2つ目のシジルを追加説明なしで製造できる

この段階を長期間作り込まず、操作仮説を確認したら統合版へ進む。

### 16.3 段階1: 3分統合ステージ

最初の正式なプレイテスト対象。

現在のGodotプロトタイプはこの段階を実装対象とする。プレイテストの入口を分かりやすくするため、
ルート選択、ステージ情報、報酬選択、次ルートへの遷移も薄い進行シェルとして先行実装している。
ただし、ルート固有戦闘や本番用の報酬コンテンツはまだこの段階の検証対象に含めない。

グリフは二分木のCombine階層を保持し、入力順に依存しない正規化構造で一致判定する。
合成後の回転は全子Primitiveの原点相対位置と向きを同じ90°単位で変換し、4回転または相殺するTransform履歴は元と同じ正規形へ畳み込む。
加工回数、通過設備、素材源IDは構造とは別の生産由来情報として召喚イベントまで保持する。
現段階では検証用データの保持までとし、生産由来情報を参照する本番リリック効果は実装しない。
工場の固定tickでは、tick開始時の入力受入可否とライン空きをスナップショットし、同じtickにライン到着・加工・次ライン送信を連鎖させない。
そのtick内に空いた入力やラインも次tickまで再利用せず、設備段数と閉塞状態に応じた決定的な遅延を保証する。
時間停止中の設定変更・再配線・テンプレート切替は仕掛品の廃棄予定数、加工状態別の種類、影響設備・ラインを表示し、Undoとキャンセルでは元状態を復元する。
変更確定後は、時間停止前後の32秒生産予測を比較して再開直後に表示する。
召喚失敗時は最も近い取得済みレシピとの差分を表示し、工場内では入力満杯、出力閉塞、合成素材不足を別の警告として色と文言で示す。
瞬間的な閉塞でも原因を読めるように警告文は最低1秒保持し、ライン・設備の警告色は現在の実状態だけを示す。
ライン中央の矢印で流向を常時表示し、入力満杯のラインは警告色へ切り替える。

#### 工場

- 素材2種類
- 加工器2種類
- 合成器1種類
- 汎用召喚器1基
- 固定予算
- DAG配線
- 無制限停止と一括編集確定

#### シジル

- 低位シジル2種類
- 高位シジル1種類
- 低位は初動と切替速度、高位は特定状況への解決力を担当する

#### 戦場

- 一本道
- 自軍召喚門1基、位置固定
- 敵2種類
- 敵編成が2〜3回変化する
- 20〜30秒先の敵予告
- 大きな編成変化は45〜60秒前に警告
- ユニットは自動戦闘し、直接命令は実装しない
- 地形、領土拡大、召喚門移動は実装しない
- 内部的な同時存在数と生成レート上限を設ける
- 通常戦闘の制限時間は3分とし、時間内に敵リーダーを撃破できなければ敗北
- 早送りは1倍、2倍、4倍を切り替え可能とし、時間停止中は無効

### 16.4 MVPから除外する要素

- 分岐結果が異なる本番用ルートマップと報酬コンテンツ（進行シェルのみ先行実装）
- リリック、ショップ、恒久強化
- 共通進化ポイントとシジル進化選択
- 敵召喚門破壊による領土拡大
- 召喚門移動
- 複数地形と高低差
- 複数のRTS命令
- 有限の時間停止ゲージ
- ライン長による魔力消費
- 分岐器、複数召喚器、循環配線
- 無制限の同時ユニット数

これらは中心仮説の成立後に、一つずつ追加して影響を測定する。

### 16.5 統合版の合格基準

以下を満たした場合、進化・領土・ローグライトの追加へ進む。

- 3分間に戦況を理由とする意味のある工場変更が1〜2回起きる
- 工場出力の変更によって前線が反転する
- 低位と高位の両方に合理的な使用場面がある
- プレイヤーが敗因を、兵種相性、生産量、配線、判断のいずれかに特定できる
- 停止中のUI操作がプレイ時間の半分を恒常的に超えない
- プレイヤーが工場と戦場の因果を説明できる
- 15分以内に本作固有の「再配線して戦局を変えた」体験が発生する
- 想定する同時召喚数で性能と可読性が維持される

以下が繰り返し起きる場合は、機能を追加せず中心ループを再設計する。

- 戦闘中に工場を一度も変更しない
- 常に最高位シジル一本が最適になる
- 変更理由が上位シジル取得だけになる
- 召喚失敗や敗北の原因を説明できない
- 工場と戦場を別々のゲームとして感じる

### 16.6 初見プレイテスト手順

最初の1戦は操作方法を口頭で補足せず、画面内の案内だけで進めてもらう。進行不能になった場合は、
詰まった画面と経過時間を記録してから最小限の補助を行う。観察者は次を時刻付きで記録する。

- 最初に選んだ工場と、戦闘開始までに迷った箇所
- 時間停止した時刻と、その直前に見ていた戦場情報
- 工場を変更した内容、本人が述べた理由、変更後に前線が変わったか
- 勝敗確定後、画面を見る前に本人が予想した主因

終了後は「何をすればよいと理解したか」「いつ、なぜ生産を変えたか」「変更で戦況が変わったか」
「勝因または敗因は何か」「もう一度遊びたいか」を同じ順番で質問する。誘導を避けるため、兵種相性や
正解の術式を質問文に含めない。少なくとも3人分を同じ形式で記録し、2人以上が同じ箇所で詰まった場合は
コンテンツ追加より先に導線またはフィードバックを修正する。
