# Sigil Factory — ルーン工場プロトタイプ仕様

## 1. 位置づけ

この文書を、現在の工場プロトタイプに関する優先正本とする。現行実装は `experiments/rune_factory/`、ルーンドメインは `src/rune/`、受入テストは `tests/run_rune_factory_tests.gd` にある。

旧来の丸・三角・四角を自由変形してCanonicalGlyphを作る方式は、現在の工場商品には採用しない。`experiments/factory_prototype/`、Sigil Lab、`SIGIL_SPEC.md`、`SIGIL_VISUAL_SPEC.md` は比較・参照用に残すが、本書と矛盾する場合は本書を優先する。

## 2. 設計目標

- ターゲットを見れば、必要なルーンの種類と個数を曖昧なく読み取れる。
- 同じ入力と設定からは常に同じ出力が得られる。
- 各設備の結果を確定前に表示し、消滅を含めて予測できる。
- 完成物は単純に読めても、素材源の距離、分岐、一括加工、再合流、帯域によって工場の解は複数残る。
- ルーン固有の強い意味は固定しない。赤・青・緑はRTS上の属性として使うが、個々の召喚結果はレシピで定める。

## 3. ルーン体系

### 3.1 24種類

ルーンは次の直積で表す。

```text
Rune = (attribute, position)
attribute = red | blue | green
position = 0..7
```

各属性に8文字、合計24文字を持つ。UIでは赤・青・緑の3つの円として並べ、各円の外周へ8文字を配置する。

各属性の内部規則は、中央を空けた3×3盤と同じである。

```text
0 1 2
3 · 4
5 6 7
```

円形表示は位置関係を読みやすくするための表現であり、移動判定はこの3×3座標で行う。

### 3.2 RunePacket

ラインを流れる商品は最大8文字の多重集合 `RunePacket` とする。

- 並び順と工場上の配置は一致判定に含めない。
- 種類ごとの個数は一致判定に含める。
- 同じルーンを複数含められる。
- 暗黙の重複除去、並び替えによる意味変更、近似一致は行わない。
- canonical表現は24種類それぞれの個数を安定順で列挙する。

例として `[赤0, 赤0]` は `[赤0]` と一致しない。

## 4. 素材源とワールド

- 24種類すべての素材源を広い盤面へ配置する。
- 素材源と中央召喚器は固定ランドマークで、ドラッグ移動・削除不可。
- 中央召喚器の近くには約2種類だけ置く。
- 中距離に6種類、遠距離に残り16種類を置き、遠出するほど使える要素を増やす。
- 同じ出力から複数ラインへ直接分岐できる。専用分配ノードは置かない。

## 5. 設備

### 5.1 中継

入力Packetを変更せず所有コピーとして返す。配線整理と距離調整に使う。

### 5.2 移動

上下左右のいずれか1マスを、Packet内の全ルーンへ同時に適用する純粋関数である。

各ルーンは独立に判定する。

- 通常スロットへ移動: 同じ属性の移動先ルーンへ変換する。
- 中央へ移動: そのルーンだけ消滅する。
- 3×3盤の外へ移動: そのルーンだけ消滅する。
- 属性をまたぐ移動: そのルーンだけ消滅する。現行設備では属性間を直接移動しない。
- 他のルーンは処理を続ける。Packet全体を拒否しない。
- 全文字が消滅した場合、その設備の出力は空となり搬送しない。

設定候補のhoverでは、変換後Packetと消滅するルーンを確定前に表示する。hoverは正式状態、輸送、Undoへ副作用を与えない。

### 5.3 属性変換

位置と個数を保ったまま、全ルーンの属性を1段変換する。

```text
赤 → 青 → 緑 → 赤
赤 ← 青 ← 緑 ← 赤
```

属性変換は移動と別設備にし、1設備が同時に2軸を変更しない。

### 5.4 抽出

1入力2出力の設備とする。

- 属性指定: 指定属性 / それ以外へ分ける。
- 位置指定: 3×3盤の指定位置 / それ以外へ分ける。
- 個数と元の種類を保つ。
- 空になった側は搬送しない。
- 暗黙にルーンを削除しない。

一括加工したくない端のルーンだけを別ラインへ送る、属性別に処理を共有するといった工場判断を作る。

### 5.5 合成

- 2〜8入力を1つのPacketへまとめる。
- 入力順と括弧は完成一致に影響しない。
- 同じルーン同士の合成を許可し、個数を加算する。
- 合計8文字を超える候補は確定前に拒否する。
- 2入力が揃うまで有効な出力を作らない。

## 6. 召喚器とターゲット

- 中央召喚器は固定された3入力を持つ。
- 入力ピンは円周上で上を基準に等角配置し、ノード移動や選択で位置を変えない。
- 入力ピンをクリックすると、その入力を選択する。
- 右上パネルには選択中入力のターゲットだけを表示する。
- ターゲットは最大8文字のRunePacketである。
- 到着Packetとターゲットの種類別個数が完全一致した時だけ召喚する。
- 未接続、輸送中、一致、不一致を別状態で表示する。

完成RunePacketの暫定表示は、ルーンを安定順に並べるだけとする。装飾的な魔法陣化は、読みやすさと工場ルールが固まった後に検討する。

## 7. 配線と輸送

- ノードは円形本体とし、名称と詳細はtooltipに置く。
- 出力は菱形、入力は中空円で表す。
- すべての方向から中央へ流せるよう、ポート位置は接続先方向に応じて円周上へ配置する。
- ライン右クリックはラインメニュー、設備右クリックは設備メニューへ統一する。
- ライン長にかかわらず搬送速度は一定とし、到着時間を `ライン長 / 搬送速度` で求める。
- 接続時にライン途中へ商品を生成しない。素材源の出力点から生成し、時間経過に沿って流す。
- ライン上ではPacketの代表ルーンと総文字数を表示する。
- 右クリック以外でラインを直接削除しない。

## 8. UI契約

- 右上に24ルーンの3属性円、選択ターゲット、現在接続中のPacketを表示する。
- ターゲット切替は選択中の召喚器入力だけへ適用する。
- 加工ノード内には現在設定と純粋関数の出力を表示する。
- 設定変更はノードの右クリックメニューから行う。
- 配置ボタンは中継、移動、属性変換、抽出、合成を提供する。
- 自動整列ボタンは表示しない。
- 色だけに依存せず、属性名・位置・ルーン字形を併用する。

## 9. 不変条件

- 入力Packetを加工関数が直接変更しない。
- preview、commit、輸送、召喚判定は同じ変換関数を使う。
- 合成・属性変換・抽出は個数を暗黙に失わない。
- 消滅を起こせるのは、現行では移動の中央・盤外だけである。
- 最大8文字を全境界で検証する。
- 循環配線を拒否する。
- 失敗した接続や設定変更で部分状態を残さない。
- 1出力の分岐先は同じ値の独立コピーを受け取る。

## 10. 受入条件

- 24素材源が存在し、近距離2・中距離6・遠距離16へ分布する。
- 四方向移動で、通常変換・中央消滅・盤外消滅をそれぞれ確認できる。
- 1つだけ消える複数ルーンPacketで、残りが正しく搬送される。
- 属性変換が位置と個数を保つ。
- 抽出の2出力を再合成すると元Packetへ戻る。
- 同一ルーン2個を合成し、1個ターゲットとは不一致、2個ターゲットとは一致する。
- 8文字は合成でき、9文字目は非破壊で拒否される。
- 同じ多重集合は配線順に関係なく一致する。
- ラインが長いほど、同じ一定速度で到着が遅くなる。
- 素材は接続直後にライン途中へ現れず、素材源から流れ始める。
- メインメニューからRune Factoryへ入り、メニューへ戻れる。

## 11. 現仕様外

- ルーン文字ごとの固定された物語上の意味
- 順序・配置・読み方向を含むスペル一致
- ルーンを完成魔法陣へ自動装飾する規則
- 自由角度、自由倍率、自由座標によるルーン変形
- 暗黙dedupe、近似一致、ランダム変異
- 8文字を超えるPacket
- 旧GlyphのMove / Rotate / Scale / Repeat / Combineをルーン商品へ混在させること
