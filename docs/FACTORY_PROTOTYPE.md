# Sigil Factory — 工場プロトタイプ実装仕様

更新日: 2026-08-22

この文書は、現在のSigil Labを基礎とする**工場プロトタイプ**の採用範囲を定義する。
現行実装については `experiments/sigil_lab/` と `tests/run_sigil_lab_tests.gd` を確認し、本書を工場プロトタイプの優先正本とする。
製品版へ向けた空間・物流・固定tickの長期仕様は `FACTORY_SPEC.md`、Glyphの正規形は `SIGIL_SPEC.md`、表示は `SIGIL_VISUAL_SPEC.md` を参照する。

---

## 1. 目的と実装境界

工場プロトタイプはSigil Labのノード文法をそのまま採用する。

```text
基本図形 / 登録グリフ
  ↓
Move / Rotate / Scale / Repeat
  ↓
Combine
  ↓
完成
```

各ノードは、入力Glyphを変更せず新しいGlyphを返す純粋関数として評価する。
同じ入力、同じ設定、同じ接続からは常に同じCanonicalGlyphを得る。

現在残っている固定tickの `FactorySimulation` と旧テンプレート群は、工場UI・設備文法の正本にはしない。
生成時間、バッファ、輸送、魔力コストは本プロトタイプの範囲外とする。

### 1.1 盤面と固定ランドマーク

- 工場盤面は開始時から広い全域を使用でき、領域アンロックや外周拡張を持たない
- 盤面中央に召喚器を1基固定する
- 丸・三角・四角の素材地点を、同じ素材がまとまった小さな資源パッチとして盤面全体へ点在させる
- 現行配置は9000×6000の盤面に各形10地点、合計30地点とする
- 中央召喚器の周囲には十分な建設余白を確保し、その外側の開始リングに全3素材を配置する
- 最寄り資源パッチも召喚器から1250以上離し、加工ノードを複数段配置できるようにする
- 遠方にも各素材の複数の選択肢を置く
- 資源パッチの距離と方向を、shapezのように経路設計へ影響する地形条件として扱う
- 素材地点と召喚器は移動・削除できない
- プレイヤーが追加する加工・反復・合成ノードは固定ランドマークの間へ配置する

Sigil Labの完成ノードは、工場盤面では中央召喚器への出力として扱う。

### 1.2 中央収束型ポート

一般的な左入力・右出力の固定配置は使用しない。工場の処理は盤面外周から中央召喚器へ収束するため、ポートは接続方向に合わせてノード外周の任意方向へ自動配置する。

- 資源パッチの出力は、そのパッチから中央召喚器へ向く外周位置に置く
- 召喚器の各入力は、接続後は実際の上流ノードへ向く外周位置に置く
- 接続操作中の未接続入力は、選択した出力側へ向けて並べる
- 同じ方向へ複数ポートが集まる場合は、接続の意味を変えず接線方向へずらして重なりを避ける
- 上下左右だけでなく斜めを含む全方位を扱い、ノード自体を回転させない
- 出力は菱形、入力は中空円として、色を外しても流れの始点と終点を区別できるようにする
- 出力のクリックまたはドラッグから入力へ接続し、入力の右クリックでその入力だけを切断する

ポートの画面上の向きはレイアウト結果であり、グラフデータの入力番号・出力番号や評価方向は変えない。

### 1.3 初期召喚目標

- 召喚器は入力1〜3を持ち、入力ごとに独立したターゲットシジルを設定する
- 各入力のターゲットは丸・三角・四角の3種からいつでも切り替えられる
- 盤面右上では入力1〜3を選択し、選択中入力のターゲットシジルだけを大きく表示する
- 現段階では加工を必要とせず、各入力へ同じ形の資源パッチを直接接続すれば召喚中になる
- 各入力は接続を1本だけ持ち、新しい直接接続で同じ入力の以前の接続だけを置き換える
- 接続形とその入力のターゲットが異なる場合は召喚せず、不一致として表示する
- 複数入力が一致していれば、それぞれの対応モンスターを同時に召喚できる

| ターゲット | 初期モンスター | 役割イメージ |
| --- | --- | --- |
| 丸 | 環霊ウィスプ | 軽量・浮遊・群体 |
| 三角 | 針獣スティンガー | 高速・突撃・軽装 |
| 四角 | 石殻ブロック | 低速・防壁・重装 |

3体はいずれも低位で量産される基本モンスターとする。形と役割の対応は、丸=連続・群体、三角=方向・攻撃、四角=安定・防御という初見の連想を利用する。

## 2. 採用するノード

| ノード | 入力 | 出力 | 設定 / 動作 |
| --- | ---: | ---: | --- |
| 基本素材地点 | 0 | 1 | 盤面に点在する丸・三角・四角の固定資源パッチ |
| 登録グリフ | 0 | 1 | 目・十字・的・星・方位 |
| 移動 | 1 | 1 | 上下左右、距離1〜6、1単位刻み |
| 回転 | 1 | 1 | 共通原点の周囲を0〜359°、1°刻み |
| 変形 | 1 | 1 | 横・縦を独立して25〜400%、25%刻み |
| 反復 | 1 | 1 | 2 / 3 / 4 / 5 / 6 / 8回の等角度反復 |
| 合成 | 2〜8 | 1 | 単純結合・中心結合・相互結合 |
| 召喚器 | 3 | 0 | 盤面中央に固定され、入力ごとに目標を持つ出力終端 |

### 2.1 基本素材

固定素材地点が供給するPrimitiveは次の3種類に限定する。

- 丸 `circle`
- 三角 `triangle`
- 四角 `square`

旧来の「輪」「棘」「枝」は標準素材として使用しない。
目、十字、牙などの意味形状は、基本図形を変形・合成して作る。

### 2.2 登録グリフ

制作者がSigil Labで作成し、再利用可能と判断した中間Glyphを1ノードとして呼び出せる。
現時点の登録集合は次の5種とする。

| ID | 表示名 | 構成概要 |
| --- | --- | --- |
| `eye` | 目 | 大小の丸を横方向へ変形して単純結合 |
| `cross` | 十字 | 横長と縦長の四角を単純結合 |
| `target` | 的 | 大小の丸を単純結合 |
| `star` | 星 | 三角と180°回転した三角を単純結合 |
| `compass` | 方位 | 十字と45°回転した十字を単純結合 |

登録グリフの外形基準は100%に揃える。
翼・牙・爪は試作後に採用を取り消しており、現在の登録集合へ含めない。

### 2.3 移動・回転・変形

- 移動は1ノードにつき上下左右のいずれか1方向だけとし、斜め移動は複数ノードの合成で表現する
- 回転はGlyphの各部品を個別に変形せず、共通原点の周囲でGlyph全体へ適用する
- 横長の四角を45°回転した場合、菱形へ再生成せず、横長の長方形全体をそのまま回転する
- 変形は横倍率と縦倍率を独立して適用する
- 合成後にMove / Rotate / Scaleした場合は、全子Primitiveと各Combine中心へ同じTransformを適用する

### 2.4 反復

反復は入力Glyph自身を含め、共通原点の周囲へ等角度で回転コピーを配置する。

- 許可数は2 / 3 / 4 / 5 / 6 / 8
- 反復内部グループは可視の結合線を作らない
- 回転対称により同じCanonicalGlyphになるコピーは重複除去する
- 中心の丸など、すべてのコピーが同じ見た目になる場合は有効なno-opとし、拒否しない
- no-op時は不可視のCombine階層を新しく作らない

## 3. 合成

合成ノードは接続済みの2〜8入力を1階層でまとめる。
同じ層の多数要素を不要な二項木へせず、1ノードで放射形・多角形・部品集合を作れるようにする。

| モード | 見える線 | 用途 |
| --- | --- | --- |
| 単純結合 | なし | 重ね合わせ、同心形、中間部品 |
| 中心結合 | 合成中心から各子へ伸びる線 | 中心と周辺の関係 |
| 相互結合 | 各子を互いに結ぶ線 | 多角形、網状構造 |

結合線はGlyphの配置から決定的に生成し、プレイヤーは線そのものを編集しない。
Primitiveや既存線と重なる区間は除去し、見える区間だけを描画する。

中心結合または相互結合で可視線が1本も残らない場合、そのモードは選択できない。
上流変更で選択中モードの線が消えた場合は単純結合へ正規化する。
これにより「見た目は単純結合と同じだが、内部IDだけ違う」完成Glyphを作らない。

## 4. 配線と分岐

グラフは有向非循環グラフとする。

- 出力から入力へドラッグして接続する
- 1入力ポートへ接続できる上流は1本だけ
- 循環、逆方向、範囲外ポート、使用済み入力を拒否する
- 通常ノードの1出力から複数の下流ノードへ直接接続できる
- 分岐先は同じ評価結果の所有コピーを受け取り、各枝で別のTransformを適用できる
- 分岐はCombine階層を増やさない

専用の分配ノードは使用しない。
「分岐」テンプレートも、1つの四角出力を4つの移動ノードへ直接接続して実現する。

固定tick生産へ接続する際の処理量・生成物個数の扱いは別途決める。
少なくとも編集文法上は、値を再利用するためだけの設備を要求しない。

## 5. 完成・表示・書き出し

### 5.1 完成操作

- 召喚器はグラフ内に1基だけ存在し、中央から移動できない
- 各中間ノードのタイトルバーにある `◎` から、その結果を召喚器へ接続できる
- `◎` は既存の完成接続を安全に置き換え、失敗時は元接続へ戻す
- 召喚器まで有効に接続されていないグラフは完成・書き出し扱いにしない

### 5.2 プレビュー

- 各ノードはその地点までを評価したGlyphを表示する
- 右側に310pxの完成プレビューを表示する
- 104 / 56 / 36pxの縮小プレビューも同時表示する
- 完成表示では自動の階層円を描かない
- `階層`ボタンを有効にした編集時だけ、Combine範囲を点線円で重ねる
- ラボ用プレビューは細い線幅を使用し、細部が潰れにくいようにする

### 5.3 JSON書き出し

上部の `グラフ出力` ボタンから、現在の全グラフを文字列として書き出す。
ダイアログは起動時に表示せず、ボタンを押した時だけ開く。

```json
{
  "format": "sigil_lab_graph",
  "version": 1,
  "canonical_glyph": "...",
  "output_node": "output_1",
  "nodes": [],
  "connections": []
}
```

書き出しには次を含める。

- 完成CanonicalGlyph
- 全ノードのID、種類、設定、編集位置
- 全接続の始点・終点・ポート

同じグラフはbyte-stableな同じJSONを返す。
現時点ではUIからの読み込み・登録名入力は未実装であり、登録は書き出したJSONを制作者が確認してデータへ追加する。

## 6. テンプレート

| テンプレート | 目的 |
| --- | --- |
| 目の印 | 丸の独立変形と単純結合を学ぶ。起動時の初期グラフ |
| 六花 | 移動した三角の6回反復と中心丸の単純結合を確認する |
| 分岐 | 1出力から4枝へ直接接続し、各枝を別方向へ移動して相互結合する |

テンプレートは正解工程を強制するゲーム内レシピではなく、ノード文法の確認・回帰テスト用とする。

## 7. 削除・保留した機能

| 機能 | 状態 | 理由 / 代替 |
| --- | --- | --- |
| 着色ノード | 削除 | 形状文法の検証へ集中する。CanonicalGlyphの互換用色IDは残るが、プレイヤーは変更しない |
| 分配ノード | 削除 | 通常出力から直接分岐する |
| 輪・棘・枝の基本素材 | 削除 | 丸・三角・四角から意味形状を組み立てる |
| 翼・牙・爪の登録グリフ | 不採用 | 試作品の見た目が基準を満たさなかったため登録しない |
| 完成表示の自動階層円 | 既定表示から削除 | 完成形を隠すため。任意の編集オーバーレイだけ残す |
| 2入力限定の合成 | 廃止 | 2〜8入力へ拡張 |
| 90°限定回転 | 廃止 | 1°単位の自由角度へ拡張 |
| 4単位刻みの移動 | 廃止 | 1〜6を1単位刻みに変更 |
| V2放射文法 / Seal Lab | 削除 | 現在のCanonicalGlyphとSigil Lab方式へ一本化 |

## 8. 受入条件

- 固定資源パッチから丸・三角・四角を使用でき、5種の登録グリフを加工素材として利用できる
- 開始時から広い工場盤面全域を利用できる
- 9000×6000の盤面全体に、丸・三角・四角の資源パッチが各10地点ずつ点在する
- 中央の建設余白より外側に開始用素材リングがあり、さらに遠方にも各素材の選択肢がある
- 召喚器と最寄り資源パッチの間へ加工ノードを複数段配置できる
- 召喚器の3入力それぞれに丸・三角・四角のターゲットシジルを設定できる
- 右上で入力を切り替えると、選択中入力のターゲットと対応モンスターが表示される
- 各入力へそのターゲットと同じ素材を直接配線すると召喚中になり、異なる素材では不一致になる
- ある入力の設定・接続・切断が、他入力の設定や召喚判定を変更しない
- 資源パッチの出力ポートが、その配置方向に関係なく中央召喚器側の外周を向く
- 召喚器の入力ポートが接続元側の外周を向き、同方向の複数入力も重ならず操作できる
- 素材地点と中央召喚器を移動・削除できない
- Move / Rotate / Scale / Repeatが入力を変更せず決定的な新Glyphを返す
- 8入力合成を1階層で保持できる
- 単純・中心・相互結合の可視差が結果へ反映される
- 可視線0本の中心・相互結合を確定できない
- 1出力から複数枝へ直接接続できる
- 中心重複のno-op反復を拒否しない
- 合成後の移動・回転・変形で、子PrimitiveとCombine中心が一緒に動く
- 完成表示では階層円が消え、編集時だけ任意表示できる
- 完成グラフだけが再現可能なJSONを出力できる
- 既存のSigil Labテストを工場移植後も同じ文法受入テストとして再利用できる
